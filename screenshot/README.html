5. 권한 실습 및 증거 기록

(1) 파일 권한 (r/w/x)의 의미

r (read) - 읽기(4) : 파일 내용을 읽거나, 디렉터리 목록을 조회할 수 있습니다.

w (write) - 쓰기(2) : 파일 내용을 수정하거나, 디렉터리 내에서 파일을 생성하고 삭제할 수 있는 권한입니다.

x (execute) - 실행(1) : 파일(스크립트·프로그램)을 실행하거나, 디렉터리로 진입(cd)할 수 있는 권한입니다.

(2) 권한 확인 (ls -l)

파일과 디렉토리의 현재 권한rwx를 확인하고, chmod 명령어를 통해 권한을 변경한 뒤 변경 전/후를 비교하였습니다.

- 파일 권한 확인 및 변경 (abcdefg.txt)

임의로 텍스트 파일(abcdefg.txt)을 생성한 후 권한 확인과 변경을 진행합니다.

touch 명령어로 파일 생성
ls -l 명령어로 권한 확인
chmod 명령어로 권한 변경 진행

터미널 · 6줄
sj_ee_6255@GNIA-C202-D06:~/E1-1/myapp$ touch abcdefg.txt
sj_ee_6255@GNIA-C202-D06:~/E1-1/myapp$ ls -l
total 12
-rw-r--r-- 1 sj_ee_6255 sj_ee_6255 6359 Nov 17 23:41 README.md
-rw-r--r-- 1 sj_ee_6255 sj_ee_6255    0 Nov 17 23:49 abcdefg.txt
-rw-r--r-- 1 sj_ee_6255 sj_ee_6255   76 Nov 17 21:55 index.html

chmod 755 명령어로

소유자는 읽기/쓰기/실행
그룹 사용자는 읽기/실행
기타 사용자는 읽기/실행

이 가능하도록 실행 권한을 추가했습니다.

터미널 · 6줄
sj_ee_6255@GNIA-C202-D06:~/E1-1/myapp$ chmod 755 abcdefg.txt
sj_ee_6255@GNIA-C202-D06:~/E1-1/myapp$ ls -l
total 12
-rw-r--r-- 1 sj_ee_6255 sj_ee_6255 6359 Nov 17 23:41 README.md
-rwxr-xr-x 1 sj_ee_6255 sj_ee_6255    0 Nov 17 23:49 abcdefg.txt
-rw-r--r-- 1 sj_ee_6255 sj_ee_6255   76 Nov 17 21:55 index.html

- 파일 권한 변경 전후 비교

변경 전 권한 (-rw-r--r--): 소유자 (읽기/쓰기),
그룹 (읽기 전용), 기타 사용자 (읽기 전용) 상태이며 실행 권한이 없습니다.

변경 후 권한 (-rwxr-xr-x): chmod 755 명령어 적용 후,

  • 왜 계속 sudo 명령어를 앞에 붙였을까 ?

개인 노트북에서는 sudo 명령어 없이도 docker 명령어가 정상적으로 실행되었으나, 공용 컴퓨터에서 docker 명령어가 정상적으로 작동하지 않았습니다.

  • 8080:80 의 의미 이해

내 컴퓨터(호스트) = localhost 컨테이너 = my-nginx-container

8080 (앞쪽 숫자) = 호스트 쪽 문 80 (뒤쪽 숫자) = 컨테이너 안쪽 문

아파트에 비유하면 localhost는 아파트 전체, 컨테이너 (my-nginx-container)는 아파트 안의 작은 방, 8080번 포트는 아파트 바깥에서 두드리는 임시 접견 문, 80번 포트는 작은 방 안에 있는 전용 손님 문으로 이해하면 좋습니다.

8-3. 컨테이너 종료/유지(attach/exec 등)의 차이 관찰 및 간단 정리

실행 중인 ubuntu:latest 컨테이너(test-con, 메인 프로세스 bash)를 대상으로 docker attach와 docker exec의 동작 차이를 확인했습니다.

핵심 차이 요약

구분 docker attach docker exec
연결 대상 실행 중인 컨테이너의 기존 메인 프로세스(PID 1)에 직접 연결 실행 중인 컨테이너 내부에 새로운 프로세스(별도 셸/명령)를 추가 실행
exit 종료 시 메인 프로세스가 종료되면서 컨테이너 상태가 Exited로 변경 추가 실행한 프로세스만 종료되고 컨테이너 상태는 Up으로 유지
정지 상태 실행 컨테이너가 Up 상태일 때 연결 가능 (Exited 상태면 먼저 docker start 필요) 컨테이너가 정지(is not running) 상태일 때 실행 불가

실습 실행

  1. 백그라운드 컨테이너 실행 및 docker attach 후 exit 종료 확인

  • docker attach test-con으로 진입해 ls, echo "attach test"를 실행한 뒤 exit로 빠져나오자 메인 bash 프로세스가 종료되면서 컨테이너가 멈췄습니다.

  • 이 직후 docker exec -it test-con bash를 호출했을 때 컨테이너가 실행 중이 아니라는 오류(is not running)가 발생하여 attach 종료가 컨테이너 정지로 이어졌음을 확인했습니다.

  1. 관찰 요약

  • docker exec: 실행 중인 컨테이너에 별도의 새 프로세스(셸, 명령)를 추가 실행한다. 해당 셸에서 exit로 종료해도 컨테이너 본체는 Up 상태를 유지한다.

  • docker attach: 실행 중인 컨테이너의 기존 메인 프로세스에 직접 연결한다. 연결된 메인 프로세스를 exit로 종료하면 컨테이너도 함께 종료(Exited)된다.

  • 비유로 차이를 이해하는 방법

실행중인 컨테이너를 영업 중인 식당에 비유하면 docker attach 는 메인 요리사와 직접 연결되는 개념이라 메인 요리사가 퇴근하면 식당 영업이 종료되는 개념, docker exec는 파트타임 보조 일꾼이 투입되는 개념으로 파트타임 직원이 퇴근해도 영업장은 정규 시간동안 그대로 유지되는 것과 같습니다.

10. 포트매핑 접속 증거

10-1. 포트 매핑이 필요한 이유

  • 컨테이너는 네트워크 네임스페이스(Network Namespace)라는 기능 때문에 내 컴퓨터(호스트)와 따로 떨어진 독립된 네트워크 공간(IP·포트 체계)을 씁니다.

    쉽게 말해 컨테이너마다 문과 번호판이 따로 달린 전용 방이 생기는 셈이라, 바깥에서 안쪽 포트로 곧장 들어갈 수 없습니다. 그래서 내 컴퓨터의 브라우저나 curl로 접속하려면 호스트 포트와 컨테이너 포트를 이어 주는 포트 포워딩(-p <호스트포트>:<컨테이너포트>) 이라는 연결 통로를 만들어 주어야 합니다.

  • 외부 접속 연결: 컨테이너 안의 포트는 바깥과 격리되어 있어서, -p 8080:80처럼 연결해 줘야 브라우저나 curl에서 localhost:8080으로 접속할 수 있습니다.

  • 포트 충돌 방지: 호스트 포트를 8080, 8081처럼 다르게 지정하면 같은 앱을 여러 개 띄울 때 포트가 겹치지 않습니다.

  • 포트 매핑(-p 8080:80) 쉽게 이해하기: 80은 컨테이너 안쪽 웹 서버가 손님을 받는 기본 출입구 번호이고, 8080은 내 컴퓨터(호스트) 바깥에서 접속할 때 쓰는 출입구 번호입니다. -p 8080:80은 내 컴퓨터의 8080번 포트로 들어온 요청을 컨테이너 내부 80번 포트로 이어 주는 연결 통로 역할을 합니다.

11-1. Git과 Github의 차이

  • git : 내 컴퓨터에서 파일의 수정 내역을 버전별로 저장하고 관리하는 프로그램입니다. 작업 기록을 남기고, 필요할 때 이전 상태로 되돌리거나 여러 작업 흐름(main 등)을 나눌 수 있습니다.
